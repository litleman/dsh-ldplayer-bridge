## 现场最小验证顺序

1. 先在 Via 安装 `DSH-Bridge-Diagnostic.user.js`。
2. 确认 `GM_xmlhttpRequest` 不为 undefined。
3. Windows Bridge 未启动时，应显示连接失败，而不是脚本崩溃。
4. 启动 Bridge 并完成 ADB reverse 后，重新检查应显示 ONLINE。
5. 记录 Composer / Send button / Assistant nodes 三项检测结果。
6. 只有以上通过，才安装完整 `DSH-GPT-Bridge.user.js`。


## 不等 DSH 开发即可先测网络链路

Windows PowerShell：

```powershell
# 先生成随机 token（也可运行 generate_token.py）
$env:DSH_BRIDGE_TOKEN = "替换为至少32字符的随机token"
python .\windows-reference\bridge_probe_server.py
```

另开一个 PowerShell 窗口：

```powershell
$ADB = "雷电14安装目录中的adb.exe"
$SERIAL = "adb devices -l 中实际显示的serial"
& $ADB -s $SERIAL reverse tcp:18765 tcp:18765
& $ADB -s $SERIAL reverse --list
```

将相同 token 填入 `DSH-Bridge-Diagnostic.user.js`，在 Via 中打开 ChatGPT 页面并点“重新检查 Bridge”。显示 `ONLINE` 即证明 Via GM 请求→ADB reverse→Windows 本机 HTTP 的基础链路已通。

该 probe server 只提供健康检查，不能处理任务；不要将它误认为完整 DSH Bridge。
